HIPAA, PHI, and public-documentation notice

HIPAA screens may display PHI, workforce identities, IP addresses, devices, routes, event metadata, before-and-after values, and other protected operational evidence. Screenshots in this public guide use redacted or demonstration information. Production access must be Provider-scoped, role-based, purpose-limited, auditable, and restricted to the minimum information reasonably necessary.

Compliance-supporting architecture

True Care System is designed to operationalize privacy, security, accountability, and minimum-necessary controls through Provider isolation, role-based permissions, PHI access logging, authentication monitoring, detailed audit history, support-session tracking, and security-event review. These capabilities support—but do not replace—the Provider's required policies, risk analysis, workforce training, business associate agreements, sanctions, incident response, and legal review.

Purpose

Audit Log Detail provides the complete evidence package for one recorded event. It combines event identity, Provider and user context, request metadata, endpoint information, device evidence, description, before-and-after values, and compliance metadata.

Event Identity

FieldFunction
Date/TimeEstablishes when the event occurred.
SeverityClassifies operational importance.
StatusShows whether the action succeeded, failed, was denied, or requires review.
Module / Action / Event TypeIdentifies the affected system area, normalized action, and event classification.
ProviderConfirms the tenant to which the event belongs.
User / Actor User / Target UserSeparates the authenticated user, acting identity, and affected user.
Individual / EmployeeLinks the event to the affected protected record where applicable.
Entity Type / Entity ID / Audit Log IDProvides durable identifiers for investigation and correlation.

Request and Device Evidence

IP Address, HTTP Method, Route, Browser, Device, Operating System, Request ID, Support Ticket ID, Impersonation Session ID, User Agent, and Description help reconstruct the technical context of the event. Copy controls allow authorized users to copy identifiers without exposing unrelated data.

Old Values and New Values

The side-by-side JSON panels preserve the record state before and after an update. This supports integrity review, dispute resolution, error correction, and determination of whether sensitive fields were changed. Reviewers should focus on material differences rather than treating every technical field as a compliance issue.

HIPAA Metadata

Metadata may include submodule, PHI category, purpose of use, access decision, support ticket, and minimum-necessary status. These fields connect the technical event to the Provider's privacy and compliance review process.

Investigation Practice

  1. Confirm the Provider and identity.

    Verify tenant scope, authenticated user, actor, target, and affected Individual.

  2. Review purpose and authority.

    Confirm that the role and purpose support the action.

  3. Compare the record states.

    Identify the exact fields changed.

  4. Correlate request evidence.

    Review route, IP, device, request ID, and support or impersonation session.

  5. Document the outcome.

    Escalate, close, or preserve the event according to Provider policy.
